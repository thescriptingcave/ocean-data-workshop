# Workshop Advanced — `notebooks/`

**Built.** Ten notebooks, ~2 h 40, against a PostgreSQL 17 + TimescaleDB database and
five ocean sources around Monterey Bay, California.

Generated by `scripts/workshop_notebooks.py` (content) and
`scripts/build_notebooks.py` (render + execute), driven by `make notebook`.

## What it assumes

The reader can already fetch a URL, is comfortable with `requests` and `pandas`, and
does not need to be told what a status code is. **Workshop Intermediate is the intended
predecessor** — see `intermediate.md`. If you add a notebook that teaches something
Intro already covers, it belongs in Intermediate.

profile are opt-in (`make db-ocean`, `--with-ocean`) because they are slow and large.

## Infrastructure

- **`notebooks/_fetch.py`** — a real `requests.Session` that overrides only `send()`,
  with the cache living there. This is deliberate: an earlier version was a wrapper
  function, and the criticism was fair — it did not teach anybody how to use `curl` or
  `requests`. Also provides `expect()` and `expect_range()`, which take **separate**
  `tol` (absolute) and `rtol` (fraction). Passing `tol=0.01` when you meant a fraction
  silently did nothing.
- **`notebooks/_sources.py`** — one manifest of every source, shared by the notebooks
  and by the prefetch script, so there is a single place a URL is defined.
- **`learning/schema.sql`** — 219 lines, the source of truth for the database schema.
- **`scripts/prefetch.py`** — warms the cache, `--install` / `--refresh`.
- **`scripts/check_cell_independence.py`** — reports, does not gate. Some cells must
  be run top to bottom; the tool makes that visible without pretending otherwise.
- **Cache** — `~/.cache/ocean-sim-harness/`, reused across phases.

## Notebook-by-notebook

| # | notebook | cells | the idea |
|---|---|---|---|
| 00 | `00_orientation` | 7 | what an access pattern is; the trap table preview |
| 01 | `01_request_three_ways` | 35 | the same fetch via curl, requests and Python; §4b gets a response *into* a DataFrame |
| 02 | `02_erddap_griddap` | 17 | querying a grid dimensionally; index syntax is part of the *name* |
| 03 | `03_gcs_object_storage` | 21 | list a bucket, read metadata, fetch one object — with no SDK |
| 04 | `04_argo_gdac_netcdf` | 19 | browse a tree, read netCDF, understand lazy loading |
| 05 | `05_copernicus_credentialed` | 13 | authenticate, then query; the CLI errors immediately without credentials |
| 06 | `06_ndbc_fixed_format` | 17 | fixed-format text and sentinel values |
| 07 | `07_gsw_domain_library` | 13 | when a domain library beats making the request yourself |
| 08 | `08_capstone_join` | 16 | join three sources — this is where the database earns its place |
| 09 | `09_trap_table` | 7 | the 36-trap reference |

Notebook 01 is deliberately the longest. It is the spine, and it carries the CSV,
ERDDAP and trap content that other notebooks would otherwise each have to reteach.

**Notebook 08 is the only one that needs the database**, and its result does not depend
on a Copernicus account. The join is trivial in pandas; the notebook teaches SQL, not
the join. That is fine and should not be "fixed".

## The trap table

36 entries in `TRAPS` in `scripts/workshop_notebooks.py`, rendered into notebook 09.
Five fields each: source, symptom, cause, consequence, and the fix or detection.

Traps are a **reference, not the spine**. Making them the backbone of the workshop was
the original structural mistake — the reader met a list of failures before meeting a
single working fetch. If you add a trap, it belongs here; if it deserves to be a
lesson, it belongs in a body notebook as a working example followed by the failure.

## CI

The workflow has five jobs. Four cover this tier, and all must pass:

1. **lint** — `ruff`
2. **unit tests** — fast, offline
3. **notebooks, offline** — executes 9 of the 10 against the cache, guarded by
   checksums so the cache cannot silently drift from what the notebooks expect
4. **integration, with the database** — TimescaleDB service, runs notebook 08

The fifth, `workshop intro`, covers Workshop Intro and is described in `intro.md`.

Offline-by-default is a deliberate choice: a public data service being briefly
unreachable should not be able to block a merge. The online path is exercised locally
and by `make fresh`.

## Constraints

- The database exists to teach **SQL and time-series aggregation**. It is not a
  requirement for any other notebook, and new notebooks should not depend on it.
- GLORYS stays opt-in. It is slow and large; the default path must stay fast.
- `notebooks/README.md` carries a pointer back to Workshop Intro. Keep it, and keep
  the two tiers' READMEs consistent with the table in the root `README.md`.
